`@snowluma/mcp` 通过 stdio 把 SnowLuma 的 OneBot 动作目录和可选执行能力接入 AI 客户端。原有工具、参数、文本结果和读写权限保持兼容；支持新版能力的客户端还可以使用补充输入、后台任务、事件订阅和消息预览面板。

本节按[当前开发分支](https://github.com/SnowLuma/SnowLuma/tree/dev/packages/mcp)维护。新能力需要包含对应更新的包；源码更新不代表 npm 包已经发布，请核对实际安装版本。目录是随包提供的快照，不代表连接的服务端支持其中所有动作。

## 工作模式

| 模式 | 何时启用 | 能做什么 |
| --- | --- | --- |
| `docs` | 未配置端点，或显式选择文档模式 | 查询目录、查看本地环境概览、生成消息草稿；不访问运行中的 SnowLuma。 |
| `read` | 配置端点后的默认模式 | 增加明确标记为只读的动作；配置事件地址后可以订阅事件。 |
| `write` | 显式设置 `SNOWLUMA_MCP_MODE=write` | 增加写动作、流式传输；配置任务目录且客户端支持时可以创建后台任务。 |

只读属性来自动作定义，不能仅凭 `get_` 等名称前缀判断。即使绕过工具列表直接调用，服务端也会检查模式。所有流式动作目前都要求写模式，包括下载。

## 准备

- 一个支持 stdio MCP 服务的客户端。
- 当前包要求 Node.js `^24.22.1 || >=26.12.1`，客户端能运行 `node` 或 `npx`。
- 执行动作需要已配置的 **OneBot HTTP 端点**，例如 `http://127.0.0.1:3000/`；WebUI 的管理端口不能替代它。
- 事件订阅另外需要 OneBot WebSocket 事件地址，不能从 HTTP 端口猜测。

同一命令支持 MCP `2026-07-28` 的发现机制和旧客户端的初始化流程，无需为旧客户端更换启动方式。高级能力是否可用还取决于客户端声明的支持情况；这里不会启动对外监听的 MCP HTTP 服务。

## 文档模式

下面是使用 `mcpServers` 配置格式的客户端示例，其他客户端请使用其等价配置：

```json
{
  "mcpServers": {
    "snowluma": {
      "command": "npx",
      "args": ["-y", "@snowluma/mcp"]
    }
  }
}
```

| 工具 | 说明 |
| --- | --- |
| `list_actions` | 按分类、读写属性、流式属性筛选，可分页。 |
| `search_actions` | 默认子串匹配，可显式开启多关键词与常用中英文同义词匹配。 |
| `get_action` | 参数、约束、返回数据结构和调用示例，支持别名。 |
| `list_categories` | 分类及动作数量。 |
| `get_runtime_info` | 默认只查看本地配置；主动检查连接需执行模式。 |
| `preview_message` | 生成纯文本和引用回复草稿，调用本身不发送消息。 |

资源 `snowluma://onebot/actions` 提供完整目录。详见[动作发现与结果](/zh/docs/mcp/actions)。

## 连接到 SnowLuma

在 WebUI 的网络适配器配置中确认 OneBot HTTP 地址与访问令牌。以下配置启用只读执行：

```json
{
  "mcpServers": {
    "snowluma": {
      "command": "npx",
      "args": ["-y", "@snowluma/mcp"],
      "env": {
        "SNOWLUMA_MCP_ENDPOINT": "http://127.0.0.1:3000/",
        "SNOWLUMA_MCP_TOKEN": "your-access-token"
      }
    }
  }
}
```

`127.0.0.1` 指 MCP 进程所在机器。跨机器连接时使用实际服务地址；访问令牌应由客户端配置注入，不要放进提示词。

执行模式提供 `query_action({ action, params? })`，以及缺少必填参数时请求用户补充的 `query_action_with_input`。完整参数仍可直接交给原工具。

## 开启写模式

在上面的 `env` 中增加 `"SNOWLUMA_MCP_MODE": "write"`，会增加 `invoke_action({ action, params?, execution? })` 和 `invoke_action_with_input`。写模式允许发消息、修改群设置等实际操作，请按所用客户端的授权策略控制调用。

下面是同时配置可选服务的 `env` 示例。只保留需要的项，目录是 **MCP 主机**上的目录：

```json
{
  "SNOWLUMA_MCP_MODE": "write",
  "SNOWLUMA_MCP_ENDPOINT": "http://127.0.0.1:3000/",
  "SNOWLUMA_MCP_TOKEN": "your-access-token",
  "SNOWLUMA_MCP_UPLOAD_ROOT": "/home/me/mcp-share",
  "SNOWLUMA_MCP_STREAM_DIR": "/home/me/mcp-downloads",
  "SNOWLUMA_MCP_TASK_DIR": "/home/me/private-mcp-tasks",
  "SNOWLUMA_MCP_EVENTS_URL": "ws://127.0.0.1:3001/event"
}
```

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `SNOWLUMA_MCP_ENDPOINT` | OneBot HTTP 端点；未设置时使用文档模式。 |
| `SNOWLUMA_MCP_TOKEN` | HTTP 和事件连接共用的访问令牌，通过授权请求头发送。 |
| `SNOWLUMA_MCP_MODE` | `docs`、`read` 或 `write`。 |
| `SNOWLUMA_MCP_TIMEOUT_MS` | 默认 `30000` 毫秒。普通请求为请求超时；流式请求分别限制连接和每次读取的空闲时间。 |
| `SNOWLUMA_MCP_STREAM_DIR` | 下载输出目录；默认系统临时目录下的 `onebot-mcp-downloads`。 |
| `SNOWLUMA_MCP_UPLOAD_ROOT` | 允许自动上传的已有目录；未设置时禁止自动读取本地文件上传。 |
| `SNOWLUMA_MCP_MAX_STREAM_BYTES` | 单文件上限，正整数，最大且默认为 `4294967296` 字节。 |
| `SNOWLUMA_MCP_TASK_DIR` | 后台任务的绝对路径私有目录；要求写模式和有效端点。 |
| `SNOWLUMA_MCP_EVENTS_URL` | 显式配置的 `ws:` / `wss:` 事件地址；不能带用户名、密码、查询参数或片段。 |

## 使用建议

1. 用 `search_actions` 找到动作，再用 `get_action` 确认参数、返回结构和标识来源。
2. 用 `get_runtime_info` 查看配置；需要联网核查时显式传入 `check_connection: true`。
3. 普通查询用 `query_action`，写入用 `invoke_action`。缺少必填参数时可用对应的 `_with_input` 工具。
4. 长传输可以创建后台任务；等待后续消息时可以订阅事件。
5. 检查业务响应和结果诊断，不把“工具调用完成”当成“消息已送达”。

## 安全边界

动作必须存在于包内目录，并通过读写模式检查。目录查询和默认环境概览不联网；事件连接仅在调用订阅工具后建立。取消或超时不会撤销已到达服务端的操作，也不会触发自动重试。普通业务失败保留 OneBot 响应，需检查 `status`、`retcode` 和结构化诊断；参数、传输及流式协议错误会显式报错。
