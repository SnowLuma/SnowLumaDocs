## 请求补充参数

`query_action_with_input` 和 `invoke_action_with_input` 沿用原工具的参数、动作目录和读写权限。只在缺少动作目录顶层 `required` 字段时请求输入，不推测条件必填项，也不替用户填写可选值。原 `query_action`、`invoke_action` 不新增询问步骤。

例如向 `invoke_action_with_input` 传入：

```json
{
  "action": "send_group_msg",
  "params": { "group_id": 20001 }
}
```

消息正文缺失时，支持表单的客户端会显示补充请求。当前表单是一个 `params_json` 字符串字段，用户填写的内容为 JSON 对象，例如：

```json
{ "message": "你好" }
```

已有参数、动作名和执行选项不能通过补充答案覆盖，多余字段和不符合结构的答案会报错。用户拒绝、取消或答案无效时不执行动作。参数齐全时直接执行；自动上传由程序生成的传输字段无需用户补填。

## 客户端兼容性

客户端需要声明表单输入能力。新版协议返回 `resultType: "input_required"`，由客户端按协议带回请求状态和输入响应；支持输入请求的旧客户端走 `elicitation/create`。不要把继续处理的结果当作最终 OneBot 响应。

不支持表单的客户端会收到明确工具错误，仍可把完整参数交给原工具。继续处理状态绑定原工具和参数，有效期十分钟，只能使用一次；重复或并发提交不会重复执行同一操作。重启会使待补充输入失效，不会重放操作。

补充输入用于收集缺失参数，**不是所有写操作的确认关卡**。已有调用是否需要用户批准，仍由客户端策略决定。

## 预览消息草稿

向 `preview_message` 传入：

```json
{
  "message_type": "group",
  "target_id": 20001,
  "text": "服务已启动",
  "reply_to": -123456
}
```

私聊使用 `private`。目标编号必须是正安全整数；可选引用编号是非零的有符号 32 位整数，负值合法。这里只支持纯文本和引用回复，正文按字面发送，不把类似消息控制码的内容解释为消息段。

所有客户端都会得到文本草稿、`can_send` 和对应 `invoke_action` 参数。调用预览工具本身不发送消息，也不查询被引用的消息。

## 交互面板

客户端声明 MCP Apps 扩展 `io.modelcontextprotocol/ui`，并支持 `text/html;profile=mcp-app` 时，工具会提供 `ui://snowluma/message-preview.html` 面板资源。

面板显示目标会话、正文及引用编号。只有用户点击发送按钮后，才通过客户端调用原 `invoke_action`；服务端仍检查写权限。读/文档模式或不支持从面板调用工具的客户端只能预览。

面板防止重复点击，失败或结果未知时不自动重试。成功提示表示服务端已接受，不能据此保证 QQ 已送达或正确渲染。面板不加载外部脚本、字体或媒体；没有面板支持的客户端继续使用文本结果。
